## 1. 오류 진단 3단계 (가장 먼저 확인할 것)

문제가 발생했을 때는 아래 순서대로 3가지 증거 자료를 확인하면 90% 이상 원인을 특정할 수 있습니다:

1. **최종 스크린샷 확인**:
   - 경로: `logs/YYYYMMDD/reservation_YYYYMMDD.png`
   - 오류가 발생한 시점의 화면 상태가 고스란히 캡처되어 있습니다. (예: "비밀번호 오류", "마감되었습니다", "시스템 점검 중")
2. **대화형 HTML 리포트 확인**:
   - 경로: `logs/YYYYMMDD/auto_login_YYYYMMDD.html`
   - 상단 `ERROR` 버튼을 클릭하여 붉은색 에러 로그만 필터링해 읽어봅니다.
3. **수동 재실행(Headful 모드)**:
   - 명령 프롬프트(`cmd`)에서 `run_automation.bat --headful --force`를 실행하여 브라우저 동작을 직접 눈으로 관찰합니다.

## 2. CASE 1: 'python' 명령어를 인식하지 못함

### 🚨 증상
배치 파일 실행 시 검은 창에 다음과 같은 메시지가 뜨며 바로 멈추거나 꺼짐:
```text
'python'은(는) 내부 또는 외부 명령, 실행할 수 있는 프로그램, 또는 배치 파일이 아닙니다.
```

### 💡 원인
Python 설치 시 `Add python.exe to PATH` 체크박스를 누락하여 윈도우 환경 변수에 파이썬 경로가 등록되지 않은 경우입니다.

### 🔧 해결 방법
1. **Python 재설치 또는 수정**:
   - Python 설치 파일(`python-3.12.x-amd64.exe`)을 다시 실행합니다.
   - [Modify] 또는 재설치를 선택하고, **`[✓] Add python.exe to PATH`**를 반드시 체크한 뒤 완료합니다.
2. **시스템 환경 변수에 수동 추가**:
   - `Win + R` ➔ `sysdm.cpl` 입력 후 Enter (시스템 속성)
   - [고급] 탭 ➔ [환경 변수] 버튼 클릭
   - `사용자 변수` 목록의 `Path`를 선택하고 [편집] 클릭
   - [새로 만들기]를 눌러 다음 두 경로 추가:
     - `C:\Users\<사용자계정>\AppData\Local\Programs\Python\Python312\`
     - `C:\Users\<사용자계정>\AppData\Local\Programs\Python\Python312\Scripts\`
   - 모든 창에서 [확인]을 누르고 열려 있는 명령 프롬프트를 닫았다가 다시 엽니다.

## 3. CASE 2: Playwright Chromium 브라우저 실행 오류

### 🚨 증상
```text
Executable doesn't exist at C:\Users\...\AppData\Local\ms-playwright\chromium-...
Please run the following command to download new browsers: playwright install
```

### 💡 원인
Playwright 라이브러리는 설치되었으나 브라우저 바이너리(Chromium)가 설치되지 않았거나 네트워크 차단으로 다운로드가 중단된 경우입니다.

### 🔧 해결 방법
명령 프롬프트(`cmd`)를 열고 아래 명령어를 순서대로 실행하여 수동으로 브라우저를 다운로드합니다:
```cmd
cd /d C:\cip
call venv\Scripts\activate.bat
playwright install chromium
```
> [!NOTE]
> 만약 사내 보안 프록시로 인해 다운로드가 차단된다면 모바일 핫스팟에 잠시 연결하여 다운로드를 완료한 후 사내망으로 복귀하세요.

## 4. CASE 3: COSMAX 로그인 실패 / 계정 잠김

### 🚨 증상
- 로그에 `[FAIL] 로그인 실패 또는 타임아웃` 메시지 기록
- 스크린샷(`reservation_YYYYMMDD.png`)에 "아이디 또는 비밀번호가 일치하지 않습니다" 또는 "비밀번호 연속 5회 오류로 계정이 잠겼습니다" 팝업 표시

### 💡 원인
- eBiz 웹사이트 비밀번호 변경 주기 도래 후 비밀번호가 바뀌었으나 `config.json`을 수정하지 않음
- 계정 잠김

### 🔧 해결 방법
1. 일반 브라우저(크롬 등)를 열고 `https://ebiz.cosmax.com/`에 직접 접속합니다.
2. 수동으로 로그인을 시도하여 계정이 정상인지 확인합니다.
3. 비밀번호가 변경되었거나 임시 비밀번호를 발급받았다면, `C:\cip\config.json` 파일을 열어 `user_pw` 항목을 새 비밀번호로 수정하고 저장합니다:
   ```json
   {
     "user_id": "S102190",
     "user_pw": "새로운비밀번호입력"
   }
   ```
4. 명령 프롬프트에서 `run_automation.bat --headful --force`로 정상 로그인을 확인합니다.

## 5. CASE 4: 10시 정각 입고예약 신청 실패

### 🚨 증상
10:00:00 정각에 요청을 전송했으나 예약이 완료되지 않고 실패함.

### 💡 원인 및 해결 방법

| 세부 원인 | 스크린샷/로그 현상 | 조치 방법 |
| :--- | :--- | :--- |
| **타사 슬롯 선점** | 해당 시간대 체크박스가 비활성화(회색)되어 있거나 마감 알림 | 0.05초 차이로 선점당한 경우입니다. 즉시 [운영 매뉴얼의 긴급 수동 신청 절차](./OPERATIONS_GUIDE.md#6-긴급-상황-시-수동-대응-절차)를 통해 16시나 기타 남은 잔여 슬롯을 수동 확보하세요. |
| **서버 지연 오픈** | 10시 정각에 체크박스가 활성화되지 않음 | 본 프로그램은 [지류]청북2층 버튼 재클릭 마이크로 루프를 0.3초마다 5회(최대 1.5초) 자동 재시도합니다. 만약 서버가 더 늦게 열린다면 `config.json`의 `"grid_max_retries": 10` (최대 3초)으로 상향 조정하세요. |
| **자급자재 품목 없음** | "납품허용 품목이 없습니다" 등 알림 | COSMAX 발주 내역에 오늘 납품 가능한 허용 품목('O')이 없는 경우입니다. 납품 관리 담당자에게 발주 상태를 확인하세요. |

## 6. CASE 5: 작업 스케줄러가 아침 09:50에 실행되지 않음

### 🚨 증상
오전 10시가 지났는데도 `logs\` 폴더에 오늘 날짜 폴더가 아예 생성되지 않음.

### 💡 원인 및 점검 항목

1. **PC 절전 모드(Sleep)**:
   - 가장 흔한 원인입니다. PC가 잠자기(절전) 상태에 빠져 타이머가 작동하지 못했습니다.
   - ➔ `Windows 설정` ➔ `전원` ➔ `절전 모드`를 **`안 함(해당 없음)`**으로 변경하세요.
2. **작업 스케줄러 '절전 모드 종료' 및 '실패 시 다시 시작' 자동화**:
   - `register_scheduler.bat` 최신 버전은 등록 시 **컴퓨터를 깨워 실행(WakeToRun)** 및 **실패 시 1분 간격 3회 자동 다시 시작** 설정을 자동으로 주입합니다.
   - 혹시 수동으로 확인하고 싶다면 `taskschd.msc` ➔ `CosmaxAutoReservation` 속성의 `조건` 및 `설정` 탭에서 확인할 수 있습니다.
3. **10시 정각 이전 세션 끊김 시 자동 복구 (Auto-Healing)**:
   - 프로그램이 09:50~10:00 대기 중 일시적 네트워크 오류를 만나더라도 `main.py`가 이를 감지하여 **5초 후 스스로 브라우저를 재부팅하여 세션을 복구**합니다.
4. **노트북 배터리 옵션**:
   - 노트북의 경우 어댑터가 분리되면 전원 절약 모드로 인해 타이머가 중단될 수 있으므로 전원 어댑터를 항상 연결해 두세요.
5. **스케줄러 작업 재등록**:
   - `register_scheduler.bat` 파일을 다시 마우스 우클릭 ➔ **[관리자 권한으로 실행]**하여 최신 설정으로 갱신합니다.

## 7. CASE 6: 사내 네트워크 / 방화벽 차단

### 🚨 증상
- 로그에 `net::ERR_CONNECTION_TIMED_OUT` 또는 `Connection refused` 발생
- 웹사이트 접속 불가

### 🔧 해결 방법
1. 사내 네트워크가 아침마다 로그인 인증(Captive Portal)을 요구하는지 확인합니다.
2. VPN 소프트웨어가 꺼져있거나 연결이 끊어졌는지 확인합니다.
3. 회사 보안 방화벽 정책에 의해 Python 프로세스의 외부 인터넷 통신이 차단되는 경우 사내 전산팀에 `python.exe` 및 ebiz 도메인 예외 처리를 요청하세요.
