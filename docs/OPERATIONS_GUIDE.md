# 운영 가이드

## 실행 명령

최초 설치와 계정 설정은 [Windows 설치 가이드](WINDOWS_SETUP_GUIDE.md)의 순서를 따릅니다. Windows에서는 `run_automation.bat`을 더블클릭하면 메뉴가 열립니다. 인수를 지정하면 메뉴 없이 해당 작업을 실행합니다.

| 작업 | Windows 메뉴 | 명령 프롬프트 명령 |
|---|---|---|
| 계정 설정 | 2번 | `run_automation.bat --setup-account` |
| 설정 검사 | 3번 | `run_automation.bat --check-config` |
| 저장 없는 점검 | 4번 | `run_automation.bat --headful --force --dry-run` |
| 실제 예약 | 5번 | `run_automation.bat --headful` |
| 정기 실행 등록·갱신 | 6번 | `run_automation.bat --register-scheduler` |
| 정기 실행 해제 | 7번 | `run_automation.bat --unregister-scheduler` |

PowerShell에서는 명령 앞에 `.\`를 붙입니다. macOS/Linux에서는 예약·점검 명령의 `run_automation.bat`을 `./run_automation.sh`로 바꿉니다. 계정 설정은 `venv/bin/python src/setup_account.py`를 사용합니다. 스케줄러 관리 옵션은 Windows BAT 전용입니다.

## 영상 녹화

기본은 꺼짐입니다. `run_automation.bat --headful --record-video`로 켜거나 `config.json`에 `"record_video": true`를 설정하면 메뉴 4·5번에서도 녹화합니다. 이번 실행만 끄려면 `--no-record-video`를 붙입니다. `headless=true`에서는 항상 녹화를 생략하므로 메뉴 6번으로 등록한 스케줄러에는 영상이 없습니다.

각 탭의 사이트 화면을 탭 생성부터 종료까지 무음으로 기록합니다. 로그인과 목표 시각 대기도 포함하므로 대기가 길면 파일 크기가 커집니다. 종료 후 `log/날짜/시간대/video_실행시각_attempt번호_시간대.webm`으로 정리되고 HTML에서 재생할 수 있습니다. 브라우저 기본 팝업은 영상에 포함되지 않으며 Windows PNG와 문구 로그로 확인합니다. 사이트 내부 안내창은 영상에 포함됩니다.

## 일상 실행

Windows 작업은 평일 09:50에 시작하며 Python이 한국 시각 목표(기본 10:00)까지 준비 후 대기합니다. Windows 로그인 세션, 네트워크, 시간대 설정을 확인하세요. 휴일에는 `SKIPPED`로 종료합니다. 수동 실행 시 목표 시각이 이미 지났으면 바로 예약 처리를 진행합니다. 작업 시작 시각에 PC가 일시적으로 실행되지 못했으면 작업 스케줄러의 시작 가능 시 즉시 실행 설정으로 보완합니다.

예약일은 사이트의 납품예정일 선택값입니다. 실행일과 다를 수 있으므로 결과의 `day`를 확인하세요. 이 프로그램은 청북2층·일반품목·미선택 납품허용(`O`) 자급자재 최대 3개 추가·파렛트 1·차량 1을 대상으로 합니다. 기존 체크는 유지합니다. 기존 예약번호가 있어도 시간대 체크박스가 활성화되어 있으면 품목을 먼저 조회하고 추가를 진행하며, 기존 파렛트·차량 수는 유지합니다. 추가 개수는 `min(3, 허용 한도 - 기존 메인 품목 수, 선택 가능한 신규 품목 수)`입니다. 한도가 8개일 때 기존 0개면 3개, 6개면 2개, 7개면 1개를 추가합니다. 기존 예약번호가 있고 이미 8개면 `EXISTING_CONFIRMED`로 저장을 생략합니다. 선택 가능한 품목이 적으면 그만큼만 추가하되 일반품목 최소 수량을 충족하지 못하면 저장하지 않습니다.

남은 수량은 메인 예약창에 표시된 종목 수로 계산하고, 기존 체크는 유지합니다. 사이트는 동일 자재코드를 중복 집계하지 않으므로 목록 9행이 종목 8개로 표시될 수 있습니다. 팝업 체크 수나 목록 행 수를 종목 수로 대신하지 않습니다. 자재 선택 전과 저장 직전에 사이트 화면의 해당 시간대 허용 한도를 검사합니다. 한도를 읽지 못하거나 저장 직전 한도가 줄어 초과하면 중단합니다. 기존 품목은 삭제하지 않습니다.

## 저장과 팝업 처리

1. 자급자재 조회 → 미선택·활성 상태의 `O` 항목을 계산된 개수만큼 체크 → **추가**를 누릅니다.
2. 메인 예약 품목이 기존 수보다 계산된 개수만큼 늘었는지 확인한 뒤 **예약신청(저장)**을 누릅니다.
3. 브라우저 기본 알림·확인창은 문구를 로그에 남깁니다. Windows 화면 표시 모드에서는 해당 탭을 앞으로 가져와 창 전체를 `*_browser_dialog_01.png`처럼 캡처한 뒤 승인합니다. 캡처는 최대 4초이며 실패하더라도 문구를 기록하고 승인합니다. headless 및 Windows 외 환경에서는 문구만 기록합니다.
4. 서버 저장 응답을 검사합니다. 대기 접수는 필요한 경우 별도 대기 저장 응답까지 확인합니다.
5. 사이트 내부 완료 안내가 표시되면 문구를 로그에 남기고 `*_08_save_notice.png`로 캡처합니다. 확정·대기 문구와 대상 시간을 확인한 뒤 안내창을 닫습니다.
6. 확정·대기 목록을 다시 조회하여 같은 예약일·창고·시간·업체의 예약번호를 확인합니다.

팝업의 확인을 눌렀다는 사실만으로 저장 성공을 판단하지 않습니다. 브라우저 경고도 캡처 처리 후 자동 승인하지만, 품목 수 제한 경고는 `ERROR`로 기록합니다. 응답 대기 실패 시 제한 초과·미달 경고가 있고 저장 요청이 전송되지 않았다면 `FAILED`로 기록합니다. 요청이 이미 전송됐거나 다른 경고만 있다면 `UNKNOWN`을 유지하면서 경고 원문을 최종 실패 사유에 포함합니다. 상세 확인 방법은 [문제 해결](TROUBLESHOOTING.md)을 참고하세요.

## 결과 확인

`log/YYYYMMDD/13/`의 가장 최근 `automation_*.html` 또는 `.log`를 엽니다. 14·15시도 같은 방식입니다. `[RESULT]`에서 해당 시간대의 상태와 예약번호를, `[COMPLETE]`에서 전체 상태와 종료 코드를 확인합니다. 별도 `result.json`은 생성하지 않습니다.

이미지는 HTML과 같은 폴더에 저장합니다. 실행 시각과 `attempt1`, `attempt2` 등 재시도 번호를 파일명에 넣어 이전 파일을 보존합니다. 팝업 순서에 영향을 주는 resize 이벤트를 피하기 위해 전체 페이지 대신 현재 화면 범위만 캡처합니다. 공통 실패 화면은 각 시간대 폴더에 저장하며, 공통 로그인·준비 로그도 각 시간대 로그에 포함합니다.

- `CONFIRMED`: 저장 성공 응답과 완료 안내를 확인하고, 새 예약 목록에서 대상 예약번호를 확인했습니다. 이번 실행의 서버 검증 결과이며, 이전 로컬 기록만으로 이 상태를 반환하지 않습니다.
- `EXISTING_CONFIRMED`: 기존 서버 예약번호와 목표 품목 수를 확인해 추가 저장이 필요 없습니다. 성공 종료로 처리합니다.
- `WAIT`: 대기 등록까지 확인했습니다. 예약 확정과 다릅니다.
- `NO_CHANGE`: 이미 품목 수가 허용 한도에 도달해 추가·저장을 생략했습니다. 이번 실행에서 예약 확정을 새로 검증한 결과가 아니며 종료 코드 2로 표시합니다.
- `UNKNOWN`: 저장 결과를 확정할 증거가 부족합니다. 다음 실행에서는 이 기록 때문에 중단하지 않고 실제 예약을 다시 시도합니다.
- `SUBMITTING`: 현재 프로세스에서 같은 시간대의 조회·예약을 처리 중입니다. 프로세스 재시작 후에는 서버 내역을 다시 확인합니다.
- `EXISTING`: 이전 버전이 기존 예약번호 때문에 중단한 결과입니다. 현재는 활성화된 시간대의 기존 예약에 자재 추가를 진행합니다.
- `FAILED`: 준비 실패 또는 서버 저장 응답의 명시적 거절입니다.
- `DRY_RUN`: 저장 전까지 점검을 마쳤습니다.
- `SKIPPED`: 주말·공휴일 설정에 따라 실행을 생략했습니다. 전체 실행 상태로 기록됩니다.

전체 `[COMPLETE]`와 시간대별 `[RESULT]`를 함께 확인합니다. 일부 성공·대기·결과 미확인이 섞이면 전체 상태는 `PARTIAL_OR_REVIEW`가 될 수 있습니다.

종료 코드 0은 전체 확정/점검 완료/휴일 생략, 1은 실패, 2는 부분 완료 또는 운영자 확인 필요입니다. 스케줄러의 `0x0`과 스크린샷만으로 납품 예약 확정을 판단하지 마세요. 서버 예약 내역이 최종 기준입니다.

## 재실행

1. 서버에서 실제 예약일·시간·창고·예약번호와 대기 여부를 확인합니다.
2. 미처리 시간만 `run_automation.bat --hours 14 15 --headful`로 실행합니다.
3. `UNKNOWN` 또는 `FAILED`인 시간대는 별도 재시도 옵션 없이 체크박스 선택부터 실제 저장까지 다시 진행합니다. 예: `run_automation.bat --headful --hours 13`. 서버에 기존 예약이 있으면 기존 품목 조회 후 남은 허용 수량 이내에서 자재를 최대 3개 추가하는 흐름을 따릅니다.
4. `SUBMITTING`은 현재 실행 안에서 같은 시간대를 동시에 처리하지 않도록 막습니다. 프로세스를 다시 시작하면 COSMAX 서버 예약번호와 품목 수를 다시 확인합니다.

10시 혼잡 시 조회·화면 로딩은 회당 기본 60초, 저장 응답과 후속 대기 저장은 기본 60초 기다립니다. 저장 응답을 기다리는 동안에는 3초 뒤부터 간격을 늘려 서버 예약을 재조회하되 기존 저장 요청을 유지하고, 확인된 예약은 즉시 완료합니다. 저장 요청이 네트워크 오류, HTTP 408·429·5xx, 비정상 응답으로 끝난 경우 같은 시간대 예약이 두 번 연속 없을 때만 알림을 닫고 다시 저장합니다. 읽기 전용 조회도 HTTP 408·429·5xx 또는 통신 오류 시 최대 3회 시도합니다. 실패한 시간대는 기본 15분 동안 독립적으로 복구하며 성공한 시간대는 반복하지 않습니다. 시간대 활성화는 전체 60초 내에서 조회 간격을 1→2→4초로 늘립니다. 마감·한도·권한 등 명시적인 거절은 즉시 처리하며 저장 요청을 재전송하지 않습니다.

각 시간대는 준비·목표 시각 대기·예약·결과 기록을 독립 수행합니다. 한 탭이 준비나 체크박스 활성화를 기다리는 동안 다른 탭은 계속 진행하고, 완료된 시간대의 `[RESULT]`를 즉시 남깁니다. 최종 공통 요약과 브라우저 종료는 모든 탭이 끝난 뒤 수행합니다.

Windows headless 실행은 시간대별 콘솔을 기본 표시합니다. 기존 실행 콘솔은 첫 시간대(기본 13시), 추가 콘솔은 나머지 시간대의 해당 실행 로그를 읽습니다. 공통 로그는 모두 표시하며 로그인·브라우저·예약 프로세스는 하나로 유지합니다. 기존 스케줄러 명령에도 자동 적용되고, `--no-split-consoles`로 끌 수 있습니다. 추가 콘솔은 닫아도 예약에 영향을 주지 않고 실행 종료 시 자동으로 닫힙니다. 원래 실행 콘솔을 닫으면 전체 실행이 중단될 수 있으므로 열어 두세요. 실행 후 결과는 기존 시간대별 로그와 HTML에서 확인합니다.

예약 목록 조회 후 사이트의 추가 상태 조회와 마감 표시 반영까지 기다립니다. 체크박스가 활성화되고 등록 링크도 표시된 시간대만 진행하며, 닫힌 시간대는 해당 탭에서만 재조회합니다.

각 시간대는 현재 프로세스 안에서 하나의 작업만 처리합니다. 실패한 시간대만 전체 복구 시간 동안 다시 시도하며 성공한 시간대는 반복하지 않습니다. 재시작 후에는 로컬 완료 기록 대신 COSMAX 서버 예약번호와 품목 수를 다시 확인합니다.

## 안전한 점검

```bat
run_automation.bat --check-config
run_automation.bat --headful --force --dry-run
```

첫 명령은 로컬 설정만 검사합니다. 두 번째는 로그인·조회와 저장 전 폼 입력을 점검하며 대기 시각과 최종 저장을 생략합니다. `--force` 자체는 예약을 막지 않습니다. 슬롯이 닫혀 있으면 준비 점검이 실패할 수 있습니다. 13시만 확인하려면 두 번째 명령에 `--hours 13`을 붙입니다.

`--headful`은 탭·주소 표시줄이 보이도록 브라우저 창을 최대화하고 창 크기에 맞춥니다. 스크린샷은 현재 보이는 범위만 저장하므로 긴 목록 전체가 담기지는 않습니다. `viewport_width`/`viewport_height` 설정은 `--headless`에서만 적용됩니다.

## 기록 관리

실행 기록은 자동 삭제하지 않습니다. HTML이 참조하는 스크린샷과 녹화 영상도 함께 보관하세요. 영상은 브라우저 컨텍스트 종료 후 완성됩니다. 강제 종료 시 불완전한 파일이나 임시 이름의 영상이 남을 수 있습니다. 이전 버전의 `.reservation_state` 파일은 더 이상 사용하지 않으며 기존 파일을 자동 삭제하지도 않습니다.

설정 목록과 상태별 의미는 [README](../README.md)를 참고하세요. 계정 설정은 위 통합 메뉴·명령 또는 `config.json`을 사용합니다.
