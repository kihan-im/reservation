# 운영 가이드

## 실행 명령

최초 설치와 계정 설정은 [Windows 설치 가이드](WINDOWS_SETUP_GUIDE.md)의 순서를 따릅니다. Windows에서는 `run_automation.bat`을 더블클릭하면 메뉴가 열립니다. 인수를 지정하면 메뉴 없이 해당 작업을 실행합니다.

| 작업 | Windows 메뉴 | 명령 프롬프트 명령 |
|---|---|---|
| 계정 설정 | 2번 | `run_automation.bat --setup-account` |
| 설정 검사 | 3번 | `run_automation.bat --check-config` |
| 저장 없는 점검 | 4번 | `run_automation.bat --headful --force --dry-run` |
| 실제 예약 | 5번 | `run_automation.bat --headful` |
| 정기 실행 등록·갱신 | 6번 | `run_automation.bat --register-scheduler` |
| 정기 실행 해제 | 7번 | `run_automation.bat --unregister-scheduler` |

PowerShell에서는 명령 앞에 `.\`를 붙입니다. macOS/Linux에서는 예약·점검 명령의 `run_automation.bat`을 `./run_automation.sh`로 바꿉니다. 계정 설정은 `venv/bin/python src/setup_account.py`를 사용합니다. 스케줄러 관리 옵션은 Windows BAT 전용입니다.

## 일상 실행

Windows 작업은 평일 09:50에 시작하며 Python이 한국 시각 목표(기본 10:00)까지 준비 후 대기합니다. Windows 로그인 세션, 네트워크, 시간대 설정을 확인하세요. 휴일에는 `SKIPPED`로 종료합니다. 수동 실행 시 목표 시각이 이미 지났으면 바로 예약 처리를 진행합니다. 늦게 부팅한 PC에서 놓친 작업을 자동 보상하거나 종료된 전체 작업을 반복 실행하지 않습니다.

예약일은 사이트의 납품예정일 선택값입니다. 실행일과 다를 수 있으므로 결과의 `day`를 확인하세요. 이 프로그램은 청북2층·일반품목·미선택 납품허용(`O`) 자급자재 3개 추가·파렛트 1·차량 1을 대상으로 합니다. 기존 체크는 유지합니다. 기존 예약번호가 있어도 시간대 체크박스가 활성화되어 있으면 품목을 먼저 조회하고 추가를 진행하며, 기존 파렛트·차량 수는 유지합니다. 예를 들어 기존 3개가 선택되어 있으면 3개를 추가하여 총 6개로 진행하며, 추가 가능한 항목이 3개 미만이면 기존 선택을 유지한 채 중단합니다.

자급자재 팝업의 기존 체크 수는 조회 조건에 따라 메인 예약의 전체 품목 수보다 적을 수 있습니다. 팝업은 기존 체크 수 + 3개, 메인 예약창은 기존 전체 품목 수 + 3개로 각각 확인한 후 저장 버튼을 누릅니다. 예를 들어 메인에 8개가 있고 팝업에 기존 1개만 조회되면 팝업은 4개, 메인은 11개가 됩니다. 저장 시 품목 수 한도는 사이트가 검증합니다. 현재 자동화는 한도에 맞춰 추가 수를 줄이거나 기존 품목을 삭제하지 않습니다. 따라서 추가 후 사이트 한도를 넘으면 저장이 거절될 수 있습니다.

## 저장과 팝업 처리

1. 자급자재 조회 → 미선택·활성 상태의 `O` 항목 3개 체크 → **추가**를 누릅니다.
2. 메인 예약 품목이 기존 수보다 3개 늘었는지 확인한 뒤 **예약신청(저장)**을 누릅니다.
3. 브라우저 기본 알림·확인창은 메시지를 로그에 남기고 즉시 승인합니다.
4. 서버 저장 응답을 검사합니다. 대기 접수는 필요한 경우 별도 대기 저장 응답까지 확인합니다.
5. 사이트 내부 완료 안내의 확정·대기 문구와 대상 시간을 확인하고 닫습니다.
6. 확정·대기 목록을 다시 조회하여 같은 예약일·창고·시간·업체의 예약번호를 확인합니다.

팝업의 확인을 눌렀다는 사실만으로 저장 성공을 판단하지 않습니다. **품목 수 초과 같은 브라우저 경고도 현재 즉시 승인됩니다.** 경고로 저장 요청이 전송되지 않으면 응답 대기 시간이 지난 뒤 `UNKNOWN`이 될 수 있습니다. 상세 확인 방법은 [문제 해결](TROUBLESHOOTING.md)을 참고하세요.

## 결과 확인

`logs/YYYYMMDD/HHMMSS_ffffff/result.json`에서 전체 상태, 종료 코드, 시간대별 결과와 예약번호를 확인합니다. 같은 폴더의 HTML은 로그 수준 필터와 검색을 제공하며 `[COMPLETE]`가 최종 요약입니다. 시간대별 텍스트 로그는 `13/automation.log` 등, 스크린샷은 `attempt_1/13/` 등에 있습니다. 팝업 순서에 영향을 주는 resize 이벤트를 피하기 위해 전체 페이지 대신 현재 화면 범위만 캡처합니다.

- `CONFIRMED`: 저장 성공 응답과 완료 안내를 확인하고, 새 예약 목록에서 대상 예약번호를 확인했습니다. 이전 로컬 확인 기록을 유지한 경우도 포함합니다.
- `WAIT`: 대기 등록까지 확인했습니다. 예약 확정과 다릅니다.
- `UNKNOWN`: 저장 결과를 확정할 증거가 부족합니다. 실패로 단정해 다시 저장하면 안 됩니다.
- `SUBMITTING`: 동작 중이거나 중간에 프로세스가 종료됐습니다.
- `EXISTING`: 이전 버전이 기존 예약번호 때문에 중단한 결과입니다. 현재는 활성화된 시간대의 기존 예약에 자재 추가를 진행합니다.
- `FAILED`: 준비 실패 또는 서버 저장 응답의 명시적 거절입니다.
- `DRY_RUN`: 저장 전까지 점검을 마쳤습니다.
- `SKIPPED`: 주말·공휴일 설정에 따라 실행을 생략했습니다. 전체 실행 상태로 기록됩니다.

전체 `status`와 시간대별 `results`를 함께 확인합니다. 일부 성공·대기·결과 미확인이 섞이면 전체 상태는 `PARTIAL_OR_REVIEW`가 될 수 있습니다.

종료 코드 0은 전체 확정/점검 완료/휴일 생략, 1은 실패, 2는 부분 완료 또는 운영자 확인 필요입니다. 스케줄러의 `0x0`과 스크린샷만으로 납품 예약 확정을 판단하지 마세요. 서버 예약 내역이 최종 기준입니다.

## 재실행

1. 서버에서 실제 예약일·시간·창고·예약번호와 대기 여부를 확인합니다.
2. 미처리 시간만 `run_automation.bat --hours 14 15 --headful`로 실행합니다.
3. `UNKNOWN`이며 서버에 미등록인 것이 확인되었으면 해당 시간에 한해 `--hours 14 --retry-unknown`을 추가합니다.
4. `SUBMITTING`은 재시도 옵션으로도 덮어쓰지 않습니다. 작업 관리자에서 실행 중인 프로그램을 확인하고, 서버 처리 여부와 `logs/reservation_state.sqlite3`의 해당 기록을 운영 담당자가 함께 검토합니다. DB 전체 삭제는 재신청 방지 기록을 잃게 하므로 사용하지 않습니다.

예약 전 단계 실패만 목표 시각 이전에 최대 5회 복구합니다. 저장이 시작된 후에는 일부 성공 시간대를 포함한 전체 자동 재시도를 하지 않습니다. 동시에 실행해도 같은 DB의 저장 권한은 시간대별로 한 실행만 획득합니다. 서로 다른 PC나 다른 로그 폴더에는 이 제약이 공유되지 않습니다.

## 안전한 점검

```bat
run_automation.bat --check-config
run_automation.bat --headful --force --dry-run
```

첫 명령은 로컬 설정만 검사합니다. 두 번째는 로그인·조회와 저장 전 폼 입력을 점검하며 대기 시각과 최종 저장을 생략합니다. `--force` 자체는 예약을 막지 않습니다. 슬롯이 닫혀 있으면 준비 점검이 실패할 수 있습니다. 13시만 확인하려면 두 번째 명령에 `--hours 13`을 붙입니다.

`--headful`은 브라우저를 전체 화면으로 열고 창 크기에 맞춥니다. 스크린샷은 현재 보이는 범위만 저장하므로 긴 목록 전체가 담기지는 않습니다. `viewport_width`/`viewport_height` 설정은 `--headless`에서만 적용됩니다.

## 기록 관리

실행 기록은 자동 삭제하지 않습니다. HTML이 참조하는 스크린샷도 함께 보관하세요. `reservation_state.sqlite3`는 결과 폴더와 함께 보존합니다. 로그는 실행 중 파일에 기록하지만 강제 종료 직전 큐의 일부 메시지는 남지 않을 수 있습니다. 저장 직전 상태는 별도 SQLite 트랜잭션으로 남깁니다.

설정 목록과 상태별 의미는 [README](../README.md)를 참고하세요. 계정 설정은 위 통합 메뉴·명령 또는 `config.json`을 사용합니다.
